# Фотографии и альбомы

Раздел фотографий использует Go-сервис profiles для альбомов, подписей,
координат, архива и комментариев; media хранит файлы и проверяет доступ перед
выдачей содержимого. Страница фронтенда: `/photos` и фото конкретного профиля.

## Возможности

- Вкладки «Фото» и «Альбомы», сетка по годам, обложки и количество фото.
- История фото профиля и пользовательские альбомы.
- Создание и редактирование альбома: название до 128 символов, описание до 512.
- Просмотр альбома: все пользователи или только владелец. Комментарии:
  все пользователи, только владелец или никто.
- Загрузка до 10 изображений за раз (до 25 МБ каждое), предпросмотр, выбор целевого альбома.
- Архивирование, восстановление и удаление; выбор нескольких фотографий.
- Просмотр фото, подпись до 2000 символов, комментарии и координаты.
- Карта OpenStreetMap с выбором фотографии. Координаты вводятся вручную;
  EXIF не извлекается. Карта загружается с OpenStreetMap при открытии этого режима.

Альбомы стены, сохранённых фотографий и отметок людей пока не являются
отдельными автоматическими коллекциями. Существующая история аватаров
отображается отдельным системным альбомом; её элементы не участвуют в
массовом удалении и архивировании пользовательских фотографий.

## Контракт

| Метод и путь | Назначение |
| --- | --- |
| GET /v1/profiles/{handle}/photos | Доступные зрителю альбомы |
| POST /v1/profiles/me/photo-albums | Создать альбом |
| PUT /v1/profiles/me/photo-albums/{albumID} | Изменить настройки |
| POST /v1/profiles/me/photo-albums/{albumID}/photos | Прикрепить свой загруженный файл |
| PUT /v1/profiles/me/photos/{photoID} | Полностью заменить подпись, архив и координаты |
| DELETE /v1/profiles/me/photos/{photoID} | Удалить фото и комментарии из галереи |
| GET, POST /v1/profiles/photos/{photoID}/comments | Прочитать последние 100 комментариев / добавить |
| GET /v1/profiles/photo-media/{mediaID}/visibility | Проверить доступ к содержимому |

Полная схема генерируется командой `task generate:swagger`.

## Приватность и хранение

media передаёт проверенный bearer-токен в profiles при каждом запросе
изображения, включая Range. При недоступности проверки файл не выдаётся.
Решение о доступе не кэшируется; ответы содержимого имеют `Cache-Control:
private, no-store`. Фронтенд передаёт токен в заголовке и отображает Blob URL,
не помещая токен в адрес изображения.

Если один файл встречается в нескольких альбомах, применяется наиболее
строгое ограничение: закрытая, архивная или удалённая запись запрещает
выдачу этого файла посторонним. При удалении остаётся служебная запись,
чтобы старая ссылка не становилась публичной; комментарии удаляются атомарно.
Бинарный файл остаётся в media. Файлы, вообще не связанные с галереей,
сохраняют существующую модель доступа media.

## Запуск и проверка

```sh
task db:migrate SERVICE=profiles SCHEMA=profiles
docker compose up -d --build --no-deps profiles media gateway
task test:integration:gallery
npm --prefix frontend run build
```

`PROFILES_MEDIA_URL` задаёт адрес media для проверки владельца и типа файла;
Compose устанавливает `http://media:8105`. `MEDIA_PROFILES_URL` используется
для проверки видимости.

Интеграционная проверка создаёт изолированный PostgreSQL на порту 55433,
проверяет репозиторий с одним соединением в пуле и выполняет up/down/up
миграции 00008. Общий старый `task db:smoke` отдельно обнаруживает ошибку
отката 00002: колонка avatar_url уже удалена откатом 00004. Применённые
старые миграции в рамках этой задачи не изменялись.
